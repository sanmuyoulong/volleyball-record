# 本机控制台

游客仍可直接使用 `/record/` 的计分和技术统计。`/console/` 是新的本机工作台，首次访问会转到 `/login/`，点击“进入本机控制台”即可使用。

这里的演示身份不是真实账号，也不提供安全访问控制或云端备份。无需密码，会话保存在当前标签页的 sessionStorage；刷新保留，退出或关闭标签页后重新进入。退出不会删除记录。

## 工作流程

1. 在队伍库创建队伍，可手填或导入 CSV / XLSX 名单。导入先预览，再带入表单。
2. 创建独立比赛，或者先创建赛事、加入参赛队伍，再手动选择两队建立对阵。比赛设置日期、时间、场馆、城市、场次、性别、赛制和规则。
3. 在比赛详情中分别进入计分、主队技术统计、客队技术统计。三份记录共用比赛编号与基础信息，技术计数相互独立。
4. 没有开始正式计分时，可填写共同手动比分。完成后在详情确认比赛结束，校验获胜局数与局比分后纳入赛事积分榜。
5. 开始正式计分后，技术统计和详情引用计分记录。原手动比分保留，但不再作为赛果来源。需要在计分页完成赛后确认，才纳入积分榜。技术得分不会自动修改正式比分。
6. 统计表仍支持二传专项、二传在场时进攻效率、分析报告和 PDF 打印。每支队伍单独导出统计表与报告。
7. 定期在“备份与迁移”导出完整控制台备份。

比赛记录页的“另存到控制台”复制当前游客草稿为新的独立比赛，并保留原草稿。不会按队名或日期自动合并，也不会自动挂入某个赛事。新建受管理的比赛通过控制台进行，避免清空旧比赛。

## 快照与管理

- 队伍库 → 赛事参赛名单 → 比赛名单均为快照。库中的后续修改不会修改历史记录。编辑比赛信息默认保留当前名单，必须主动选新的队伍才会替换赛前快照。
- 开始记录后锁定比赛队伍、性别、赛制和规则。比赛时间和场地仍可在详情中纠正。计分的赛前名单和技术统计名单分别由各自记录工具校验。
- 赛事分组支持 1–8 组。比赛手动创建，不自动编排赛程。赛事积分按胜场、局胜率、小分胜率排序。
- 归档可恢复，不物理删除。归档比赛不纳入积分榜。赛事归档后需要恢复才能继续添加队伍和比赛，已有比赛的归档单独管理。
- 暂不支持把已有比赛移动到另一个赛事。

## 存储与迁移

`src/console-repository.js` 提供异步数据仓库接口，目前用 IndexedDB 数据库 `volley-console-v1`，包含 `teams/events/matches/meta` 四张表。每次更新在事务内核对 revision，旧标签页无法覆盖另一标签页已保存的内容。遇到冲突应导出当前备份，再重新载入。当前采用单个记录页面写入同一比赛；并发协作不是本版功能。

保存提示只在事务成功后显示“已保存”。站内跳转先等待保存；关闭页面时，若仍有未保存内容会提醒。受管理记录可导出当前编辑内容，保存失败也能保留修改。

首次进入控制台时，会把旧赛事索引和逐场计分归档复制到数据库，同时保存原始 localStorage 内容。迁移可重复执行，不会重复创建；旧键不删除，游客技术统计草稿不自动合并。只剩摘要的旧比赛标记“原记录缺失”；不生成虚构的数据。旧 `/tournaments/` 链接会跳转到控制台赛事页。

完整 JSON 备份保留全部关联、主客队统计、二传归属及原始迁移备份。导入采取新增方式，编号冲突时统一重新编号并更新关联，不覆盖现有记录。旧计分 JSON 和技术统计 JSON 会导入为新的独立比赛。格式不完整或赛事引用缺失的备份会被拒绝。

网站、不同浏览器、离线 HTML 的存储位置独立，通过导出/导入迁移。清理浏览器或退出隐私模式可能丢失数据；离线文件移动或改名后也应检查原存档是否仍可访问。

## 后续接入云端

`src/session.js` 的会话接口和异步仓库接口是接入真实认证与数据库的边界。下一阶段应同时实现认证、服务器鉴权和云端数据仓库，由用户选择要迁移的本机数据；不能仅凭浏览器传入的身份判断所有权。

之后再加入组织者与记录员权限、只读赛事页面和离线恢复。多设备同时写入需要事件日志、版本和幂等机制，不能直接放开当前整场快照覆盖模式。

## 验证

- `npm test`：记录规则、名单、技术统计、二传、比分来源与赛后确认。
- `npm run test:console`：登录演示门槛、游客复制、名单导入、赛事与比赛、主客队统计隔离、正式比分、跨页冲突、备份往返、移动端和退出。
- `npm run test:console:storage`：迁移幂等、原数据保留、缺失记录、修订冲突、备份重编编号及无效备份拒绝。
- `npm run build:offline` 后运行 `npm run test:console:offline`：单文件内同样的管理流程。
- `npm run test:offline`：移动/改名单文件、无网络请求、游客计分、CSV/XLSX、二传、JSON、打印和导航。

浏览器测试默认使用本机 Chrome。控制台测试默认访问 `http://127.0.0.1:4174`，可通过 `CONSOLE_TEST_URL` 覆盖。先启动 `PORT=4174` 的预览服务，再运行网页版测试；离线测试不需要服务器。
